# sop-propose

把模糊或长程目标收束成可自治推进的边界和工作面。

## 适用前提

用户有目标，但 objective、边界、验收、物理落脚点或可执行工作面尚未清楚。目标既可以是局部设计，也可以是无法预先枚举全部模块和路径的长程意图。

## 需要做

- 先判断目标尺度，只展开会影响当前行动的维度。
- 明确目标、裁决原则、边界、验收标准和物理落脚点。
- 对长程目标建立必要的目标坐标系，显影已知缺口、未知缺口和需要验证的工作面；不写 roadmap、milestone 或固定任务清单。
- 对模块边界负责：说明状态所有权、能力暴露、数据流、协作关系和验证边界；多个模块管理相似复杂度时应合并或重划。
- 找出最先暴露且最阻塞后续推进的工作面。
- 优先用 TEL decisions、constraints、当前 repo 和已有对话消解选项。
- 暴露仍需裁决的选项空间，并只在既有约束无法裁决时问用户。
- 产出足够后结束当前 framing，把目标合同和首个工作面交回共享 router。
- 后续证据改变边界或缺口时重新显影，不维护失真的固定计划。

## 不需要做

- 不写长方案文档。
- 不重复讨论 TEL 已定 decision。
- 不把 principles 写成无法裁决的空话。
- 不要求用户预先列出所有模块，也不把推测缺口当成事实。
- 不创建文件骨架；本 action 只定义所需物理落脚点及其责任。
- 不在上下文已经足够时继续停留在 propose。
