# sop-expand

把远意图展开成可工作的缺口场。

## 适用前提

用户给出较远目标或大尺度任务，但具体模块、路径、边界、验收内容或下一批工作面无法预先枚举。

## 需要做

- 识别目标涉及的用户路径、系统模块、数据流、外部依赖、部署面和风险面。
- 对比当前状态与目标状态，显影已知缺口、未知缺口和需要验证的工作面。
- 用当前上下文、TEL、kanban Done、patterns、decisions、代码和参考案例补齐目标空间。
- 把缺口归属到可执行 action：`explore`、`propose`、`scaffold`、`conform`、`migrate`、`diagnose`、`reduce`、`replicate`、`review`、`ship`。
- 找出最先暴露、最阻塞后续推进的工作面。
- 每轮 action 后根据新证据更新缺口场，而不是维护固定计划。

## 不需要做

- 不写 roadmap、milestone、时间表或固定任务清单。
- 不要求用户预先列出所有模块。
- 不把推测缺口当作已验证事实。
- 不替代具体 action 的局部判断。
- 不把缺口场写成项目愿景、产品介绍或方案文档。

## TEL 写入

只有目标展开形成可复用展开方法、长期边界、跨任务行动规范或明确后续任务，并通过 TEL 写入闸门时写入。
